1. What Tributary does

A drug-discovery lab treats cells with a compound, measures thousands of proteins on a mass spectrometer and runs analysis software on the raw files. Tributary stores the outputs of that software in one place, checks them, locks them as versioned releases, and lets scientists query, chart and compare them across every experiment they have access to.

ExperimentCells + compound + controls, described as samples and contrasts
→
InstrumentMass spectrometer produces raw files
→
Analysis toolsDIA-NN, limma, CurveCurator, MaxQuant…
→
Tributary releaseChecked, versioned, immutable table
→
InsightResults pages, Explore, Compare, protein and compound pages

Three properties make the results trustworthy:

  • Nothing changes silently. A published release can never be edited; a correction becomes a new release.
  • Every number has a source. Each release records the input file, its checksum, the importer and every transformation applied. The lineage page shows the chain.
  • Every action is audited. Imports, publications and exports are logged with who, when and why.

2. Running the application

Tributary runs on your own computer for development and demos. Four small services run as Node.js and Python processes, and the database, file storage and sign-in server run in Docker.

First-time setup (once per computer)

  1. Get the code: git clone https://github.com/sprinriver/Tributary.git then cd Tributary.
  2. Enable pnpm: corepack enable.
  3. Install dependencies: pnpm run bootstrap. This installs the exact locked versions for Node.js and Python and never changes the lockfiles.
  4. Start the supporting services: docker compose up -d --wait. This starts Postgres on port 5432, S3 storage on 8333 and Keycloak on 8080, and waits until all three are healthy.
  5. Create the database tables: pnpm db:migrate.
  6. Load the demo registry: pnpm db:seed. This adds 2 programmes, 12 experiments, their samples, compounds and the search index. It is safe to run again.

Start the application (every time)

  1. Make sure Docker Desktop is running, then docker compose up -d --wait (does nothing if the services are already up).
  2. Run pnpm dev and leave this terminal open. It starts the web app, API, query service and statistics service. Press Ctrl+C in this terminal to stop them all.
  3. Open http://localhost:5173 and click Sign in.

Load the demo datasets in one command

The seed registers experiments but no data releases, so Explore and the charts start empty. With pnpm dev running, open a second terminal in the project folder and run:

pnpm demo:data

It uploads the demo tool outputs from fixtures/experiments/, imports them, and publishes four datasets, each on a new published experiment version: limma results for ONC-DIA-05 and IMM-DIA-06, the DIA-NN protein matrix for ONC-DIA-05, and the CurveCurator dose-response fits for ONC-DIA-01. It usually finishes in under a minute and prints one line per dataset. Running it again is safe: datasets that already exist are skipped. The work is recorded in the audit log under the user "Demo loader". It is for local development only and refuses to run in production.

Your data lives on your computer. Experiments and datasets are stored in the Docker containers on the machine where you created them; they are not in Git. On a new computer, run the setup above and then pnpm demo:data to get the same demo data back.

Alternative: everything in one container

For a quick demo without installing Node.js or Python, build and run the single-container image:

docker build -f deploy/huggingface/Dockerfile --build-context source=. -t tributary-space .
docker run --rm -p 7860:7860 -e PUBLIC_URL=http://localhost:7860 -e TRIBUTARY_ADMIN_PASSWORD=<choose one> tributary-space

Open http://localhost:7860; sign in as scientist / scientist, or as admin with the password you chose. Data resets every time the container restarts.

Windows

  • pnpm fails with "Cannot find module … pnpm.cjs". The corepack bundled with older Node.js 24 releases does not understand pnpm 12. Upgrade Node.js to 24.15 or newer, or install a newer corepack (npm install -g corepack@0.35.0) and delete the cached copy in %LOCALAPPDATA%\node\corepack\v1\pnpm\12.15.0.
  • The one-container image stops with set: pipefail: invalid option name. Git converted the shell scripts to Windows line endings. In the project folder run git config core.autocrlf input, then, only when you have no uncommitted changes (they would be lost), git rm -rq --cached . followed by git reset --hard. Rebuild the image afterwards.
  • WSL2 is the smoothest option if you hit other differences: clone the project inside the Linux file system (for example ~/Tributary) rather than on a Windows drive.

3. The datasets, explained

The demo contains 12 registered experiments across two programmes: ONC (oncology) and IMM (immunology). pnpm demo:data imports and publishes the four datasets below so that every chart in the application has data.

Dataset (tool)Experiment designOne row is…Question it answers
ONC-DIA-05 protein quant
DIA-NN · 942 rows		 MCF-7 breast-cancer cells. 3 samples with compound CPD-000005 at 1 µM, 3 with DMSO (solvent only) One protein in one sample, with its measured intensity Did each sample run well? Do replicates agree? Do treated samples differ overall?
ONC-DIA-05 differential abundance
limma · 157 rows		 Same experiment; contrast CPD-000005@1 µM vs DMSO One protein: log2 fold change and adjusted p-value Which proteins did the compound change, in which direction, and how confidently?
ONC-DIA-01 dose response
CurveCurator · 157 rows		 HeLa cells. CPD-000001 at 0 (vehicle), 1 nM, 10 nM, 100 nM, 1 µM and 10 µM, 2 samples each One protein: fitted dose curve, regulation, pEC50 Which proteins respond to the compound, and at what concentration (potency)?
IMM-DIA-06 differential abundance
limma · 157 rows		 K-562 leukaemia cells; contrast CPD-000006@1 µM vs DMSO One protein: log2 fold change and adjusted p-value Does a second compound act like the first? (used on the Compare page)

How each one connects to a real decision

  • Protein quant → data quality. Before anyone believes a result, the team checks that every run identified a similar number of proteins and that missing values are low. A bad run is caught here, not in a meeting three months later.
  • Differential abundance → mechanism of action. "Our compound is designed to act on pathway X. Do the proteins in pathway X move?" Unexpected strong changes are early warnings of off-target effects.
  • Dose response → potency and selectivity. If the intended target responds at 10 nM and an unwanted protein only at 5 µM, there is a safety window. Medicinal chemists use these numbers to choose which molecule to make next.
  • Comparing contrasts → shared or distinct biology. Overlapping hits between two compounds suggest a shared mechanism; distinct hits can explain different side-effect profiles.

4. Key terms

TermMeaning
ContrastThe comparison being tested, written numerator vs denominator, e.g. CPD-000005@1 µM vs DMSO.
log2 fold change (log2 FC)log2(numerator ÷ denominator). +1 = doubled, −1 = halved, 0 = no change. +2.2 means about 4.6 times higher in treated cells.
Adjusted p-valueConfidence that a change is real after correcting for testing many proteins at once (Benjamini–Hochberg here). Smaller is stronger; 0.05 is a common cut-off.
pEC50−log10 of the concentration (in molar) giving half the maximal effect. Higher = more potent; pEC50 7 = 100 nM, pEC50 8 = 10 nM.
Regulation (dose response)CurveCurator's call for each curve: up, down, not (no response) or unclear.
ReleaseAn imported, validated version of a dataset. Staged = under review; Published = locked and visible in Explore.
Experiment versionA locked description of the experiment (samples, contrasts, files). Changes create a new version; results pages show the latest published version.
Display thresholds are not statistical tests. The default volcano thresholds (|log2 FC| ≥ 1 and adjusted p ≤ 0.05) only colour the chart. The statistics come from the source tool (limma, CurveCurator); Tributary does not recompute them.

5. Step by step: from file to insight

Step 1Sign in and find the experiment

  1. Open http://localhost:5173 and click Sign in. Use scientist / scientist (can create and edit) or viewer / viewer (read-only).
  2. Click Experiments in the left menu. Filter by name, assay type, programme or date.
  3. Click an experiment name, for example ONC-DIA-05: contrast in MCF-7.

Tip: press Ctrl+K anywhere to search experiments, samples, proteins and compounds by keyword.

Step 2Check the experiment design before the data

Results only make sense if the design is right. On the experiment page:

  1. Overview shows the assay, species, version and its permanent identifier (URN).
  2. Samples lists every sample: cell line, compound, dose and replicate. Confirm there are enough replicates per group (here 3 DMSO and 3 treated).
  3. Contrasts shows exactly what is compared with what. Read it as numerator vs denominator.

Step 3Bring the data in: upload and quality check

Shortcut for the demo data. pnpm demo:data performs Steps 3 to 5 for the four demo datasets automatically. Follow these steps by hand to learn the workflow, or when importing your own files.

Published experiment versions are locked, so new files go into a new draft version.

  1. Click Create version. A Draft version 2 appears.
  2. Open the Files tab, set Role to processed (tool output), click Choose files and then Upload. Files go directly to storage, in parts, and resume if interrupted.
  3. Wait for the status to change from Checking… to QC passed. Tributary has recognised the format and recorded a checksum, so the exact file can be proven later.

Step 4Import the file as a dataset

  1. Click Import… next to the file. Tributary suggests the right importer from the file contents (here limma topTable).
  2. Give the dataset a clear name, e.g. ONC-DIA-05 differential abundance. Later imports with the same name become new releases of the same dataset.
  3. For statistical results, choose the Contrast the file belongs to. For dose-response files, enter the compound and the exact doses used (for this demo: CPD-000001; 0, 1, 10, 100, 1000, 10000 with dose scale 1e-9, i.e. nanomolar).
  4. Click Import.

Step 5Review the staged release, then publish

The import creates a staged release. Before publishing, check:

  • Quality rules: every error rule must pass (p-values between 0 and 1, one row per protein per contrast, and so on). Warnings need a judgement. In the demo, a warning says the synthetic SYNP… IDs are not real UniProt accessions, which is expected.
  • Column statistics: row count, empty values, minimum and maximum. Sudden gaps signal a parsing problem.
  • Provenance: original column names and each transformation applied.
  • First rows: a sanity check of the actual values.

Click Publish release and give a reason (it goes into the audit log). Then go back to the experiment and Publish the draft version so the Results page shows the new data.

Step 6Read the experiment's Results page

On the experiment, click Results. Read the page from top to bottom:

  1. Methods: an automatically written paragraph describing the experiment and tools. Copy methods pastes it into a report.
  2. QC: proteins identified per run, missing values, variability (CV) per condition and intensity distributions. Look for a run that stands out.
  3. Volcano: each dot is a protein. Right = increased, left = decreased, higher = more confident. Red and blue dots pass both thresholds.
  4. Top hits: the same proteins as a sortable table. Click a protein to open its page.
  5. Pathway enrichment and Interaction network: check whether hits cluster in known biology.
Insight. QC is clean: about 150 proteins identified in every run, 2.5–3.8 % missing values and similar intensity distributions, so the comparison is fair. CPD-000005 strongly increases AKT1 (log2 FC +2.20, about 4.6×, adjusted p 4.5×10−17) and decreases PARP1 (−1.59, adjusted p 4.2×10−9). Only 9 of 157 proteins pass both thresholds, so the effect is focused rather than global.

Step 7Read dose-response curves for potency

Open ONC-DIA-01 → Results. The Dose-response panel draws the measured points and the fitted curve for each protein.

  1. Use Regulation to show up and/or down curves, and FDR at most to keep only confident fits.
  2. Set how many Curves to show and how to Sort them (by FDR by default), then click Apply.
  3. Read each curve: where it crosses half-way is the EC50. A curve that drops at 10–100 nM shows a potent effect; one that drops only at 10 µM shows a weak effect.
Insight. Most responding proteins decrease with dose, but they do so at different concentrations: some fall between 10 nM and 100 nM, others only above 1 µM. That spread is the selectivity window. A few proteins (for example P07437 and SYNP0094) increase. Twelve vehicle (dose 0) points are left off the log axis, as the page states.

Step 8Ask questions across experiments in Explore

Explore queries every published dataset you are allowed to see, without writing code.

  1. Click Explore. Choose a Dataset kind (e.g. differential abundance) and tick Latest published versions only.
  2. Under Filters, click + Rule and build a condition, e.g. adj_p_value < 0.05. Add more rules or groups as needed (AND / OR / Not).
  3. Optionally Add join to attach other information, such as target annotations or experiment details.
  4. Click Run query. The table shows the matching rows; Columns chooses what to display and Export downloads them (exports are audited).

Then scroll to Chart:

  1. Pick a Chart type. For a volcano: X = log2_fc, Y = adj_p_value, Colour = contrast_label, Label = gene_names, Label top hits = 10.
  2. Click Apply. Hover over points for details; draw a box or lasso to select a cluster.
  3. Provenance shows exactly which releases and settings produced the chart; Download PNG/SVG saves it.
  4. Save view stores the query and chart so colleagues can reopen it; Copy as code gives the same query in Python or R.

For protein-level data (dataset kind protein quant), a PCA shows whether samples group by treatment: Row label = sample_key, Values = log2_intensity, Feature = protein_group.

Insight, and a caution. The DMSO samples (S01–S03) and treated samples (S04–S06) do not separate cleanly on PCA. This is consistent with the volcano: only about 9 of 157 proteins change, so the overall profile is dominated by ordinary sample-to-sample variation. A weak PCA does not mean "no effect"; look at the targeted statistics.

Step 9Compare two compounds

  1. Click Compare, tick 2 to 6 contrasts and set the thresholds (default |log2 FC| ≥ 1, adjusted p ≤ 0.05).
  2. Click Compare. Read the three panels:
    • Fold-change scatter: each protein's change in one contrast against the other. Points on the diagonal behave the same way in both.
    • Hits shared between contrasts: how many significant proteins are unique to each contrast or shared.
    • Overlap table: every protein significant in at least one, with both values side by side (a dot marks significance).
Insight. The two compounds act very differently: they share only one hit, SYNP0078, and it moves in opposite directions (+1.62 with CPD-000006, −1.52 with CPD-000005). AKT1 rises with CPD-000005 but is flat with CPD-000006, while CPD-000006 changes TP53, EGFR, SRC and PTEN, which CPD-000005 leaves alone. Bear in mind that the cell lines also differ (K-562 vs MCF-7), so the next experiment should test both compounds in the same cells.

Step 10Follow one protein, and trace any number to its source

Click any protein link (or go to /proteins/<UniProt ID>). The protein page gathers everything known about it: annotations, every experiment where it was measured, its dose-response curves and modification sites. Add to triage puts it on the team's shortlist; Watch subscribes you to alerts about it (shown under Alerts at the top right).

To prove where a result came from, open a release and click Lineage. It shows the chain from file to experiment version to release (and on to charts and views made from it). The table underneath lists each step with its status.

Admins can also open Audit to see every import, publication and export, with the reason given.

A repeatable routine for any new experiment

  1. Check the design (samples, replicates, contrast direction).
  2. Check QC before looking at any hit.
  3. Find the hits on the volcano and top-hits table.
  4. Ask "is this biology?" with pathway enrichment and the interaction network.
  5. Check potency with dose-response data where it exists.
  6. Put it in context with Compare, protein pages and Explore across experiments.
  7. Record and share: Save view, Copy methods, the Report button, and triage for follow-up.

8. Good practice and limits

  • Enter doses and contrasts exactly as run. A wrong dose scale shifts every pEC50; a reversed contrast flips every fold change.
  • Thresholds are for display. Changing the volcano cut-offs changes the colours, not the statistics.
  • Replicates matter. With three per group, modest changes will not reach significance; absence of a hit is not proof of no effect.
  • Different cell lines are different experiments. Compare across them for hypotheses, then confirm in matched conditions.
  • Nothing is imputed or filtered silently. Any transformation appears in the release's provenance; read it before drawing conclusions.
  • This guide uses synthetic data. Identifiers beginning SYNP / SYNTH are invented. Named proteins (AKT1, PARP1, TP53…) carry synthetic values and say nothing about real compounds.
  • External services. The 3D-model panel on protein pages fetches from AlphaFold DB and shows an error when that service is unreachable from your network; all other features work offline.
