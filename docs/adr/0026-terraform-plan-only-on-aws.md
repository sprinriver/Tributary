# 0026 — Terraform for the customer's AWS account: plan in CI, apply by people
Date: 2026-11-02 · Status: accepted
## Context
- ARCHITECTURE §12 places Tributary in each customer's own AWS account. Customers' platform teams review and
  apply infrastructure themselves.
- The plan rules: never run `terraform apply` or `destroy`; don't install terraform, tflint or checkov in the agent
  environment; plan only with a sandbox profile the owner provides (none was).
## Decision
- **Twelve reusable, region-agnostic modules** (`infra/terraform/modules`) composed by `envs/dev`. `envs/prod` is
  created by people from `envs/dev`.
- **Validation in CI:** `pnpm run infra:validate` (fmt, validate, tflint, checkov 3.4.0) runs in the CI `infra`
  job, which installs the tools on the GitHub runner. Locally the script only checks for the tools and stops if
  they are missing.
- **Plan in CI, never apply:** `.github/workflows/aws.yml` builds arm64 images to ECR and runs `terraform plan`
  only when the customer sets `AWS_PLAN_ROLE_ARN` (OIDC). Fork PRs get no token. Apply is a human step
  (`docs/DEPLOY.md`).
- **Choices:**
  - ECS Fargate on Graviton with Service Connect (`query:3100`, `compute:8000`) instead of an internal ALB.
  - CloudFront serves the SPA from S3 (Origin Access Control) and `/api/*` to an ALB that accepts only
    CloudFront's origin-facing prefix list.
  - One customer-managed KMS key for S3, RDS, logs, SQS, ECR and secrets.
  - RDS keeps its master password in Secrets Manager. App secrets are generated by Terraform.
  - Explicit availability zones (default `<region>a`, `<region>b`), so the network never moves when AWS adds a zone.
  - The S3 Terraform backend with lock files (Terraform ≥ 1.10), so no DynamoDB table.
- **IAM:** write actions are scoped to account ARNs. Only Batch Describe/List actions, which have no
  resource-level permissions, keep `*`. The KMS key policy's `*` means "this key"; checkov's IAM checks are skipped
  there inline, with that reason.
- **Checkov skips** are listed with reasons in `infra/terraform/.checkov.yaml`. Each is a cost or policy choice
  the customer can reverse: replication, WAF, Multi-AZ, CloudFront origin failover and similar.
## Consequences
- **Not yet run:** `terraform plan` against a real account (no sandbox profile was provided). The first run needs
  the customer's `AWS_PLAN_ROLE_ARN`.
- **Dev database TLS:** dev uses `DATABASE_SSLMODE=no-verify`, which encrypts but does not check the certificate.
  Production should bake in the RDS CA and use `verify-full`.
- **Not in Terraform yet:** CloudWatch alarms. `docs/RUNBOOK.md` lists them.
